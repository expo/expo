Google Play requires every app with a store listing to complete the [Data safety form](https://support.google.com/googleplay/android-developer/answer/10787469) in Play Console. The form covers every library in your app, so your answers include what `expo-observe` sends to Expo Observe. This guide lists that data and the form answers that match it.

> **info** You are responsible for the accuracy of your Data safety declarations. This guide covers only the data that `expo-observe` and Expo Observe handle. Combine it with the data practices of the rest of your app before you submit the form.

## What expo-observe sends off the device

`expo-observe` sends metrics, events, and logs to Expo Observe over HTTPS using the OpenTelemetry Protocol. Every record carries the same set of resource attributes:

- The [Expo Services client ID](/eas/observe/reference/client-id/), a random identifier for one installation of your app
- A session ID, generated for each app launch
- Device model name and identifier
- Operating system name and version
- The device language tag
- Network type, such as Wi-Fi or cellular
- App name, version, and build number
- The Expo Update channel, runtime version, and the ID of the running update
- The Expo SDK version, React Native version, and the environment tag

Like every network request, each dispatch also exposes the device's IP address to the server.

What else is sent depends on the features you use:

| Feature                                                                                                 | Data sent                                                                                                       | Default |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------- |
| [Startup metrics](/eas/observe/reference/metrics/) and [update download time](/eas/observe/eas-update/) | Launch, render, interactive, bundle load, and update download timings                                           | On      |
| [Error reporting](/eas/observe/errors/)                                                                 | Exception type, message, stack trace, React component stack, native crash signal, and termination reason        | On      |
| [Navigation integrations](/eas/observe/integrations/expo-router/)                                       | Route names, route parameters, and per-route timings. Remove sensitive parameters with `filteredParams`.        | Opt in  |
| [Network traces](/eas/observe/configuration/#network-traces)                                            | Request method, URL with sensitive query parameters redacted, status code, request and response sizes, and host | Off     |
| [User-defined events](/eas/observe/events/) and global attributes                                       | The event names and attribute values your code passes                                                           | Opt in  |

The library does not read the device's location, contacts, or files. It does not send a name, email address, or account ID unless your code adds one to an event, attribute, or error message. Keep personally identifiable information out of those values.

## What Expo stores

Expo Observe stores every record it receives for 90 days, then deletes it. Deletion runs in monthly batches, so a record can remain for up to 120 days. After deletion, Expo keeps only per-app event counts for billing. See [data retention](/eas/observe/reference/metrics/#data-retention).

Expo uses the IP address of each dispatch to derive an approximate location, such as the country. Expo processes all Observe data on your behalf, as your service provider, under Expo's data processing agreement. See [privacy explained](https://expo.dev/privacy-explained) for what Expo collects across its services.

You can stop Expo Observe from accepting data at any time with the [data ingestion toggle](/eas/observe/configuration/#turn-off-data-ingestion) in the Expo dashboard.

## Complete the Data safety form

The form has three parts that your Expo Observe usage affects. The answers below assume you send data to Expo Observe. If you use a [custom endpoint](/eas/observe/configuration/#custom-endpoint), the same records go to your endpoint, and you declare what that backend stores instead.

### Data collection and security

| Question                                                              | Answer                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Does your app collect or share any of the required user data types?   | **Yes**. Performance metrics are diagnostics, the client ID is a device identifier, and the IP address is used to infer approximate location.                                                                                                                                                                      |
| Is all of the user data collected by your app encrypted in transit?   | **Yes** for Expo Observe. The library sends every record over HTTPS. Answer for your whole app.                                                                                                                                                                                                                    |
| Do you provide a way for users to request that their data is deleted? | Google allows **Yes** when you give users a way to request deletion, or when collected data is deleted or anonymized automatically within 90 days of collection. Expo Observe deletes data after 90 days, in monthly batches. The answer covers your whole app, so base it on your own deletion practices as well. |

### Data types

Select these data types for Expo Observe:

- **App info and performance > Diagnostics**: startup, navigation, update download, and network timings. Always collected.
- **Device or other IDs**: the client ID. Google lists installation identifiers in this category. Always collected.
- **Location > Approximate location**: Google's definition includes location inferred from an IP address. Always collected.
- **App info and performance > Crash logs**: JavaScript errors and native crashes. Collected when error reporting is on, which is the default, or when your code calls `Observe.reportError()`.
- **App activity > App interactions**: route names and user-defined events. Collected when you use a navigation integration or log events.

### Data usage and handling

For each selected data type, the form asks how the data is collected and used. Use these answers for every data type above:

| Question                                    | Answer                                            |
| ------------------------------------------- | ------------------------------------------------- |
| Is this data collected, shared, or both?    | Collected                                         |
| Is this data processed ephemerally?         | No                                                |
| Is this data required, or can users choose? | Required, unless your app lets every user opt out |
| Why is this user data collected?            | Analytics                                         |

The data is **collected** rather than **shared** because Expo acts as your service provider. Google's form treats a transfer to a service provider, an entity that processes data only on your behalf and on your instructions, as collection by your app, not as sharing with a third party.

Google's **Analytics** purpose covers monitoring app health, diagnosing crashes, and improving performance, which is what Expo Observe does.

The data is **required** by default because the library dispatches from every release build. You can declare it **optional** only if every user, in every region, can turn it off. To offer that, call `configure({ dispatchingEnabled: false })` when the user opts out. [Sampling](/eas/observe/configuration/#sampling) does not make the data optional, because the user does not control it.

## Expo Update

If your app also includes `expo-updates`, add the declarations in [App store privacy declarations for Expo Update](/eas-update/store-privacy-declarations/). Both libraries use the same client ID, so the **Device or other IDs** entry covers both.
