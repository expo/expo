Issue to PR is an automated workflow in which a coding agent changes your code for a GitHub issue and opens a pull request (PR). Then [Agentic CI](/eas/agentic-workflows/agentic-ci/) tests the PR on a remote iOS Simulator. You review a PR that has a verdict and evidence.

## How Issue to PR works

When a person adds the `agent` label to an issue, these steps run. The highlighted steps run on EAS Workflows and Expo Simulators:

<IssueToPrDiagram />

1. A GitHub Action starts the Issue to PR workflow on EAS.
2. A coding agent reads the issue and its comments, and changes the code.
3. The workflow pushes the change to the branch `agent/issue-<number>`, and opens a PR that closes the issue.
4. Agentic CI tests the PR on an Expo Simulators session, and posts the verdict on the PR.

Only people who can add labels to issues can start the agent. Read each issue before you add the label, because the agent follows the text of the issue.

## Set up your project

Do these steps one time for your project.

<Step label="7">

### Add a GitHub token to EAS

The workflow pushes a branch, opens a PR, and adds comments to the issue. It needs a GitHub token for these tasks.

On GitHub, create a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new). Under **Repository access**, select only your repository. Give it these permissions:

- **Contents:** Read and write
- **Issues:** Read and write
- **Pull requests:** Read and write

In the project dashboard, open **Project settings** > [**Environment variables**](https://expo.dev/accounts/[account]/projects/[project]/environment-variables). Add these variables to the **preview** environment:

| Name                | Value                                                        | Visibility |
| ------------------- | ------------------------------------------------------------ | ---------- |
| `GITHUB_TOKEN`      | The GitHub token                                             | Secret     |
| `GITHUB_REPOSITORY` | The owner and the name of the repository, such as `acme/app` | Plain text |

The job removes the GitHub token from the environment of the agent. An agent that can run shell commands can still read the variables of the job. So give the token access only to this repository. See [What the agent can do](#what-the-agent-can-do) for more information.

</Step>

Issue to PR also needs [Agentic CI](/eas/agentic-workflows/agentic-ci/), because Agentic CI tests each PR that the agent opens. Add Agentic CI first.

## Add the Issue to PR workflow

<Step label="1">

### Add the GitHub helper

The job script uses this file to read the issue, open the PR, and add comments:

```js .eas/agents/github.mjs
import { readFile } from 'node:fs/promises';

const repository = process.env.GITHUB_REPOSITORY;
const token = process.env.GITHUB_TOKEN;

if (!repository || !token) {
  console.error(
    'GITHUB_REPOSITORY or GITHUB_TOKEN is not set. Add both to the preview environment of the EAS project.'
  );
  process.exit(1);
}

async function request(method, path, body) {
  const response = await fetch(`https://api.github.com${path}`, {
    method,
    headers: {
      accept: 'application/vnd.github+json',
      authorization: `Bearer ${token}`,
      'content-type': 'application/json',
      'x-github-api-version': '2022-11-28',
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  if (!response.ok) {
    throw new Error(
      `GitHub returned ${response.status} for ${method} ${path}: ${await response.text()}\nCheck that GITHUB_TOKEN can read and write contents, issues, and pull requests in ${repository}.`
    );
  }
  return response.json();
}

const repo = `/repos/${repository}`;
const [command, ...args] = process.argv.slice(2);

switch (command) {
  case 'issue': {
    const issue = await request('GET', `${repo}/issues/${args[0]}`);
    const comments = await request('GET', `${repo}/issues/${args[0]}/comments?per_page=50`);
    console.log(
      JSON.stringify(
        {
          title: issue.title,
          body: issue.body,
          comments: comments.map(comment => comment.body),
        },
        null,
        2
      )
    );
    break;
  }
  case 'comment': {
    await request('POST', `${repo}/issues/${args[0]}/comments`, {
      body: await readFile(args[1], 'utf8'),
    });
    break;
  }
  case 'open-pull-request': {
    const [branch, title, bodyFile] = args;
    const owner = repository.split('/')[0];
    const open = await request('GET', `${repo}/pulls?state=open&head=${owner}:${branch}`);
    if (open.length > 0) {
      console.log(open[0].html_url);
      break;
    }
    const { default_branch: base } = await request('GET', repo);
    const pullRequest = await request('POST', `${repo}/pulls`, {
      head: branch,
      base,
      title,
      body: await readFile(bodyFile, 'utf8'),
    });
    console.log(pullRequest.html_url);
    break;
  }
  case 'author-email': {
    const user = await request('GET', '/user');
    console.log(`${user.id}+${user.login}@users.noreply.github.com`);
    break;
  }
  default:
    console.error(
      `Unknown command "${command}". Use issue, comment, open-pull-request, or author-email.`
    );
    process.exit(1);
}
```

</Step>

<Step label="2">

### Add the job script

```sh .eas/agents/make-change.sh
#!/usr/bin/env bash
set -euo pipefail

: "${ISSUE_NUMBER:?No issue number. Pass -F issue_number=<number>.}"
: "${GITHUB_TOKEN:?GITHUB_TOKEN is not set. Add it to the preview environment.}"
: "${GITHUB_REPOSITORY:?GITHUB_REPOSITORY is not set. Add it to the preview environment.}"

PROJECT_DIR=$(pwd)
WORK_DIR=/tmp/agent-change
BRANCH="agent/issue-$ISSUE_NUMBER"
GITHUB_HELPER="$PROJECT_DIR/.eas/agents/github.mjs"
PUSH_URL="https://x-access-token:${GITHUB_TOKEN}@github.com/${GITHUB_REPOSITORY}.git"

git clone --depth 1 "$PUSH_URL" "$WORK_DIR"
git -C "$WORK_DIR" remote set-url origin "https://github.com/${GITHUB_REPOSITORY}.git"
ln -s "$PROJECT_DIR/node_modules" "$WORK_DIR/node_modules"
printf 'node_modules\nagent-output/\n' >> "$WORK_DIR/.git/info/exclude"
mkdir -p "$WORK_DIR/agent-output"

{
  cat .eas/agents/make-change.md
  printf '\n## Issue #%s\n\n' "$ISSUE_NUMBER"
  node "$GITHUB_HELPER" issue "$ISSUE_NUMBER"
} > "$WORK_DIR/agent-output/prompt.md"

cd "$WORK_DIR"
env -u EXPO_TOKEN -u EXPO_TOKEN_SIMULATOR -u GITHUB_TOKEN \
  timeout 20m bash .eas/agents/run-agent.sh agent-output/prompt.md change || true

if [ -z "$(git status --porcelain)" ]; then
  {
    printf '## Issue to PR\n\nThe agent did not change any file.\n\n'
    cat agent-output/summary.md 2> /dev/null || true
  } > /tmp/comment.md
  node "$GITHUB_HELPER" comment "$ISSUE_NUMBER" /tmp/comment.md
  exit 1
fi

TITLE=$(head -n 1 agent-output/summary.md 2> /dev/null || true)
TITLE=${TITLE:-"Change for issue #$ISSUE_NUMBER"}
{
  tail -n +2 agent-output/summary.md 2> /dev/null || true
  printf '\n\nCloses #%s\n' "$ISSUE_NUMBER"
} > /tmp/pull-request.md

AUTHOR_EMAIL=$(node "$GITHUB_HELPER" author-email)
git checkout -b "$BRANCH"
git add -A
git -c user.name="EAS agent" -c user.email="$AUTHOR_EMAIL" commit -m "$TITLE"
git push --force "$PUSH_URL" "HEAD:refs/heads/$BRANCH"
PR_URL=$(node "$GITHUB_HELPER" open-pull-request "$BRANCH" "$TITLE" /tmp/pull-request.md)

printf '## Issue to PR\n\nThe agent opened %s.\n' "$PR_URL" > /tmp/comment.md
node "$GITHUB_HELPER" comment "$ISSUE_NUMBER" /tmp/comment.md
```

The script does these tasks in this order:

1. It clones the default branch, and removes the GitHub token from the remote URL of the clone.
2. It reads the issue and its comments, and writes the prompt for the agent.
3. It removes the Expo and GitHub tokens from the environment, and runs the agent in the `change` mode.
4. If the agent changed no file, it adds a comment with the reason to the issue, and stops.
5. It commits the change, pushes the branch, and opens a PR. Then it adds a comment with the PR link to the issue.

</Step>

<Step label="3">

### Add the prompt

The job script adds the issue and its comments to the end of this prompt:

```md .eas/agents/make-change.md|wrap
You make one change in this Expo project. The issue at the end of this prompt describes the change.

1. Read the issue and its comments.
2. Make the smallest change that does what the issue asks. Use the style of the code around the change.
3. Do not add dependencies. Do not change files in .eas, .github, or node_modules.
4. If the project has a tsconfig.json file, run `npx tsc --noEmit`. Fix each error that your change causes. Do not fix errors that were there before your change.
5. Write the file agent-output/summary.md. Line 1 is a pull request title. Then describe the change in two to five sentences. Tell what a user sees, because Agentic CI tests that.

If you cannot make the change, do not change any file. Then write line 1 of agent-output/summary.md as "No change: <reason>".
```

The PR description comes from the summary of the agent. Agentic CI tests what the description says.

</Step>

<Step label="4">

### Add the EAS workflow

```yaml .eas/workflows/issue-to-pr.yml
name: Issue to PR

on:
  workflow_dispatch:
    inputs:
      issue_number:
        description: The number of the issue that the agent works on
        type: string
        required: true

jobs:
  change:
    environment: preview
    env:
      ISSUE_NUMBER: ${{ inputs.issue_number }}
    steps:
      - uses: eas/checkout
      - uses: eas/install_node_modules
      - name: Make the change and open a pull request
        run: bash .eas/agents/make-change.sh
      - uses: eas/upload_artifact
        if: ${{ always() }}
        with:
          type: other
          name: issue-to-pr-log
          path: /tmp/agent-change/agent-output/**/*
```

</Step>

<Step label="5">

### Add the GitHub Action

EAS Workflows does not start on issue events. This GitHub Action starts the EAS workflow when a person adds the `agent` label to an issue:

```yaml .github/workflows/agent-label.yml
name: Start the agent

on:
  issues:
    types: [labeled]

jobs:
  start:
    if: github.event.label.name == 'agent'
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with:
          node-version: 22
      - run: npm ci
      - run: npx --yes eas-cli@latest workflow:run .eas/workflows/issue-to-pr.yml -F issue_number=${{ github.event.issue.number }} --non-interactive
        env:
          EXPO_TOKEN: ${{ secrets.EXPO_TOKEN }}
```

The Action installs the dependencies with `npm ci`, because EAS CLI reads the app config. If your project uses another package manager, change this command.

</Step>

## Start the agent on an issue

Create an issue that asks for one small feature. Tell the agent where the feature goes and what a user sees:

<Terminal
  cmd={[
    '$ gh issue create --title "Add a reset button to the counter" --body "On the home screen, add a Reset button next to the counter. A tap sets the count to 0."',
  ]}
/>

The command prints the address of the issue. The address ends with the issue number. Add the `agent` label to the issue:

<Terminal cmd={['$ gh issue edit <number> --add-label agent']} />

The GitHub Action starts the Issue to PR workflow on EAS.

## Read the result

When the agent finishes, the issue gets a **Issue to PR** comment with a link to the PR:

- The branch of the PR is `agent/issue-<number>`.
- The description of the PR is the summary of the agent, and ends with `Closes #<number>`.

Then Agentic CI tests the PR, and posts an **Agentic CI** comment with the verdict. To try the feature yourself, select **Try this build in your browser** in that comment.

If the agent changes no file, the issue gets a comment with the reason. The log of the agent is in the artifacts of the Issue to PR workflow run.

To ask for another version, change the text of the issue. Then remove the label and add it again:

<Terminal
  cmd={[
    '$ gh issue edit <number> --remove-label agent',
    '$ gh issue edit <number> --add-label agent',
  ]}
/>
