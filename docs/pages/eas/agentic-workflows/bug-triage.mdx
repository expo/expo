Bug triage is an automated workflow in which a coding agent tries to reproduce a bug report on a remote iOS Simulator. The report comes from a GitHub issue or from TestFlight feedback. When the agent sees the bug, [Issue to PR](/eas/agentic-workflows/issue-to-pr/) opens a pull request (PR) with a fix, and [Agentic CI](/eas/agentic-workflows/agentic-ci/) tests the fix.

## How Bug triage works

The highlighted steps run on EAS Workflows and Expo Simulators:

<BugTriageDiagram />

1. For TestFlight feedback, the workflow creates a GitHub issue with the comment of the tester, the device, and links to the screenshots.
2. It starts an Expo Simulators session with a build of the default branch.
3. A coding agent follows the steps in the report and writes a verdict: `REPLICATED` or `NOT-REPLICATED`.
4. The workflow posts the verdict on the issue. For a `REPLICATED` bug, it adds the `agent` label, which starts Issue to PR.

The agent tests a build of the default branch, not the build that the tester used.

## Add the Bug triage workflow

<Step label="1">

### Update the GitHub helper

This version of **.eas/agents/github.mjs** adds two commands to the version from Issue to PR: `add-label` and `create-issue`. Replace the file:

```js .eas/agents/github.mjs
import { readFile } from 'node:fs/promises';

const repository = process.env.GITHUB_REPOSITORY;
const token = process.env.GITHUB_TOKEN;

if (!repository || !token) {
  console.error(
    'GITHUB_REPOSITORY or GITHUB_TOKEN is not set. Add both to the preview environment of the EAS project.'
  );
  process.exit(1);
}

async function request(method, path, body) {
  const response = await fetch(`https://api.github.com${path}`, {
    method,
    headers: {
      accept: 'application/vnd.github+json',
      authorization: `Bearer ${token}`,
      'content-type': 'application/json',
      'x-github-api-version': '2022-11-28',
    },
    body: body ? JSON.stringify(body) : undefined,
  });
  if (!response.ok) {
    throw new Error(
      `GitHub returned ${response.status} for ${method} ${path}: ${await response.text()}\nCheck that GITHUB_TOKEN can read and write contents, issues, and pull requests in ${repository}.`
    );
  }
  return response.json();
}

const repo = `/repos/${repository}`;
const [command, ...args] = process.argv.slice(2);

switch (command) {
  case 'issue': {
    const issue = await request('GET', `${repo}/issues/${args[0]}`);
    const comments = await request('GET', `${repo}/issues/${args[0]}/comments?per_page=50`);
    console.log(
      JSON.stringify(
        {
          title: issue.title,
          body: issue.body,
          comments: comments.map(comment => comment.body),
        },
        null,
        2
      )
    );
    break;
  }
  case 'comment': {
    await request('POST', `${repo}/issues/${args[0]}/comments`, {
      body: await readFile(args[1], 'utf8'),
    });
    break;
  }
  case 'add-label': {
    await request('POST', `${repo}/issues/${args[0]}/labels`, { labels: [args[1]] });
    break;
  }
  case 'create-issue': {
    const [title, bodyFile, ...labels] = args;
    const issue = await request('POST', `${repo}/issues`, {
      title,
      body: await readFile(bodyFile, 'utf8'),
      labels,
    });
    console.log(issue.number);
    break;
  }
  case 'open-pull-request': {
    const [branch, title, bodyFile] = args;
    const owner = repository.split('/')[0];
    const open = await request('GET', `${repo}/pulls?state=open&head=${owner}:${branch}`);
    if (open.length > 0) {
      console.log(open[0].html_url);
      break;
    }
    const { default_branch: base } = await request('GET', repo);
    const pullRequest = await request('POST', `${repo}/pulls`, {
      head: branch,
      base,
      title,
      body: await readFile(bodyFile, 'utf8'),
    });
    console.log(pullRequest.html_url);
    break;
  }
  case 'author-email': {
    const user = await request('GET', '/user');
    console.log(`${user.id}+${user.login}@users.noreply.github.com`);
    break;
  }
  default:
    console.error(
      `Unknown command "${command}". Use issue, comment, add-label, create-issue, open-pull-request, or author-email.`
    );
    process.exit(1);
}
```

</Step>

<Step label="2">

### Add the job script

```sh .eas/agents/reproduce.sh
#!/usr/bin/env bash
set -euo pipefail

: "${BUILD_ID:?No simulator build. Check the build or repack job of this run.}"
: "${ISSUE_NUMBER:?No issue number. Check the intake job, or pass -F issue_number=<number>.}"

mkdir -p agent-output/evidence
node .eas/agents/github.mjs issue "$ISSUE_NUMBER" > /tmp/issue.json

{
  cat .eas/agents/reproduce.md
  printf '\n## Bug report\n\n'
  cat /tmp/issue.json
} > agent-output/prompt.md

export EXPO_TOKEN="$EXPO_TOKEN_SIMULATOR"
npx --yes eas-cli@latest simulator:start --platform ios --type agent-device \
  --build-id "$BUILD_ID" --name "Issue #$ISSUE_NUMBER triage" --tag bug-triage \
  --max-duration-minutes 30 --json > /tmp/session.json
trap 'npx --yes eas-cli@latest simulator:stop --non-interactive > /dev/null 2>&1 || true' EXIT

env -u EXPO_TOKEN -u EXPO_TOKEN_SIMULATOR -u GITHUB_TOKEN \
  timeout 20m bash .eas/agents/run-agent.sh agent-output/prompt.md device || true

VERDICT=$(head -n 1 agent-output/evidence/verdict.md 2> /dev/null || true)
VERDICT=${VERDICT:-"INCONCLUSIVE: The agent did not write a verdict. See the logs of this run."}
SESSION_URL=$(node -p 'require("/tmp/session.json").deviceRunSessionUrl')

{
  printf '## Bug triage\n\n**Verdict:** %s\n\n' "$VERDICT"
  printf -- '- [Session recording](%s)\n' "$SESSION_URL"
  printf -- '- [Agent report and screenshots](%s)\n\n' "$RUN_URL"
  printf '<details>\n<summary>Report</summary>\n\n'
  tail -n +2 agent-output/evidence/verdict.md 2> /dev/null || true
  printf '\n</details>\n'
} > /tmp/comment.md
node .eas/agents/github.mjs comment "$ISSUE_NUMBER" /tmp/comment.md

case "$VERDICT" in
  REPLICATED:*) node .eas/agents/github.mjs add-label "$ISSUE_NUMBER" agent ;;
esac
```

The script does these tasks in this order:

1. It reads the issue and its comments, and writes the prompt for the agent.
2. It starts a session with the build, and runs the agent in the `device` mode.
3. It posts the verdict and a report on the issue.
4. For a `REPLICATED` verdict, it adds the `agent` label to the issue. Then it stops the session.

</Step>

### Add the prompt

The job script adds the issue and its comments to the end of this prompt:

```md .eas/agents/reproduce.md|wrap
You try to reproduce a bug report in this project on a remote iOS Simulator. The app is installed and open on the simulator. The bug report is at the end of this prompt.

1. Read the report. Find the steps, the expected result, and the actual result. You can also read the source code of the project with your file tools.
2. Follow the steps as a user does. Run only this shell command. The job denies each other shell command. If a command is denied, continue with this command:

   npx --yes eas-cli@latest simulator:exec npx --yes agent-device@latest <command>

   Use these agent-device commands:
   - `snapshot -i` lists the elements on the screen, with references such as `@e2`.
   - `press @e2` taps an element.
   - `fill @e4 "text"` types text into a field.
   - `scroll down` scrolls the screen.
   - `screenshot agent-output/evidence/<name>.png` saves a screenshot.
   - `open <bundle identifier> --platform ios` opens the app again. The app config has the bundle identifier.

3. Save a screenshot after each step.
4. Write the file agent-output/evidence/verdict.md. Line 1 is "REPLICATED: <one sentence>" or "NOT-REPLICATED: <one sentence>". Then list each step that you did and what you saw.

Write REPLICATED only when you saw the bug yourself. Do not change the files of the project.
```

<Step label="4">

### Add the TestFlight report formatter

For TestFlight feedback, the workflow uses this script to change the feedback into the text of an issue. The issue does not include the name or the email address of the tester.

```js .eas/agents/feedback-issue.mjs
import { readFile, writeFile } from 'node:fs/promises';

const [feedbackFile, bodyFile] = process.argv.slice(2);
const result = JSON.parse(await readFile(feedbackFile, 'utf8'));
const report = result.feedback ?? result.crash ?? result;
const comment = (report.comment ?? '').trim();
const screenshots = (report.screenshots ?? []).map(screenshot => screenshot.url).filter(Boolean);

const lines = [
  '## TestFlight report',
  '',
  comment
    ? comment
        .split('\n')
        .map(line => `> ${line}`)
        .join('\n')
    : '> The tester did not write a comment.',
  '',
  `- Build: ${report.buildVersion ?? 'unknown'}`,
  `- Device: ${report.deviceModel ?? 'unknown'}, iOS ${report.osVersion ?? 'unknown'}`,
  ...screenshots.map((url, index) => `- [Screenshot ${index + 1}](${url}). The link expires.`),
];

if (result.logText) {
  const codeFence = '`'.repeat(3);
  lines.push(
    '',
    '<details>',
    '<summary>Crash log</summary>',
    '',
    codeFence,
    result.logText.slice(0, 20000),
    codeFence,
    '',
    '</details>'
  );
}

await writeFile(bodyFile, `${lines.join('\n')}\n`);

const title =
  comment.split('\n')[0] || (result.crash ? 'TestFlight crash report' : 'TestFlight feedback');
console.log(title.slice(0, 100));
```

Apple signs the links to the screenshots for a limited time, so the links in the issue expire.

</Step>

<Step label="5">

### Add the EAS workflow

```yaml .eas/workflows/bug-triage.yml
name: Bug triage

on:
  app_store_connect:
    beta_feedback:
      types: [screenshot, crash]
  workflow_dispatch:
    inputs:
      issue_number:
        description: The number of the issue with the bug report
        type: string
        required: true

jobs:
  intake:
    if: ${{ !inputs.issue_number }}
    environment: preview
    env:
      FEEDBACK_URL: ${{ app_store_connect.beta_feedback.url }}
    outputs:
      issue_number: ${{ steps.file.outputs.issue_number }}
    steps:
      - uses: eas/checkout
      - uses: eas/install_node_modules
      - id: file
        name: File the TestFlight report as a GitHub issue
        run: |
          set -euo pipefail
          EXPO_TOKEN="$EXPO_TOKEN_SIMULATOR" npx --yes eas-cli@latest testflight:feedback "$FEEDBACK_URL" --json > /tmp/feedback.json
          node .eas/agents/feedback-issue.mjs /tmp/feedback.json /tmp/issue.md > /tmp/issue-title.txt
          ISSUE_NUMBER=$(node .eas/agents/github.mjs create-issue "$(cat /tmp/issue-title.txt)" /tmp/issue.md bug testflight)
          set-output issue_number "$ISSUE_NUMBER"

  fingerprint:
    type: fingerprint
    environment: preview

  get_build:
    type: get-build
    needs: [fingerprint]
    params:
      platform: ios
      profile: preview
      simulator: true
      fingerprint_hash: ${{ needs.fingerprint.outputs.ios_fingerprint_hash }}
      wait_for_in_progress: true

  build:
    type: build
    needs: [get_build]
    if: ${{ !needs.get_build.outputs.build_id }}
    params:
      platform: ios
      profile: preview

  repack:
    type: repack
    needs: [get_build]
    if: ${{ needs.get_build.outputs.build_id }}
    params:
      build_id: ${{ needs.get_build.outputs.build_id }}
      profile: preview

  reproduce:
    needs: [get_build]
    after: [intake, build, repack]
    environment: preview
    env:
      BUILD_ID: ${{ after.build.outputs.build_id || after.repack.outputs.build_id }}
      ISSUE_NUMBER: ${{ inputs.issue_number || after.intake.outputs.issue_number }}
      RUN_URL: ${{ workflow.url }}
    steps:
      - uses: eas/checkout
      - uses: eas/install_node_modules
      - name: Reproduce the bug on a remote iOS Simulator
        run: bash .eas/agents/reproduce.sh
      - uses: eas/upload_artifact
        if: ${{ always() }}
        with:
          type: other
          name: bug-triage-evidence
          path: agent-output/evidence/**/*
```

The jobs do these tasks:

- `intake` runs only for TestFlight feedback. It creates the GitHub issue.
- `fingerprint`, `get_build`, `build`, and `repack` find or create an iOS Simulator build of the default branch.
- `reproduce` runs the job script. It gets the issue number from the `intake` job, or from `-F issue_number` in a manual run.

</Step>

## Reproduce a bug from a GitHub issue

Create an issue with the `bug` label. Write the steps, the expected result, and the actual result:

<Terminal
  cmd={[
    '$ gh issue create --label bug --title "<what is wrong>" --body "<steps, expected result, and actual result>"',
  ]}
/>

The command prints the address of the issue. The address ends with the issue number. Start the workflow on the default branch with the issue number:

<Terminal
  cmd={['$ eas workflow:run .eas/workflows/bug-triage.yml --ref main -F issue_number=<number>']}
/>

If your default branch has a different name, change `--ref`.

## Reproduce a bug from TestFlight feedback

For this path, you need a membership in the Apple Developer Program and an app with a build in TestFlight.

1. Connect your App Store Connect app to the EAS project. See [Trigger workflows from App Store Connect events](/eas/workflows/get-started/#trigger-workflows-from-app-store-connect-events).
2. Make sure that EAS has an App Store Connect API key for the app. To add one, run `eas credentials --platform ios`. The `eas testflight:feedback` command finds the app with the bundle identifier and the API key of the `production` submit profile.
3. Create the `testflight` label:

   <Terminal cmd={['$ gh label create testflight']} />

4. In the TestFlight app, take a screenshot of the bug, write a comment, and send the feedback.

App Store Connect starts the **bug-triage.yml** workflow. The `intake` job creates the issue, and then the `reproduce` job runs. Each TestFlight report creates a new issue. The workflow does not look for duplicates.

## Read the result

When the agent finishes, the issue gets a **Bug triage** comment:

- **Verdict:** `REPLICATED`, `NOT-REPLICATED`, or `INCONCLUSIVE`, with one sentence from the agent. The verdict is `INCONCLUSIVE` when the agent writes no verdict.
- **Session recording:** the session page on expo.dev, with the screen recording of the session.
- **Agent report and screenshots:** the workflow run on expo.dev. The report and the screenshots are in its artifacts. The Claude Code runner also saves its log there, and the other runners print it to the job log.
- **Report:** in a folded section, each step of the agent and what it saw.

For a `REPLICATED` bug, the workflow adds the `agent` label. Issue to PR then opens a PR with a fix, and Agentic CI tests it.

For `NOT-REPLICATED`, add the missing steps to the issue. Then run the workflow again.
