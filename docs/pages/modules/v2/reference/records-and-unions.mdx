A record is a native type that converts to and from a JavaScript object. A union is a native type that converts from one of a few JavaScript types, the same as a union type in TypeScript.

## Records

<LanguageSupport feature="records" />

Add `@Record` to a data class in Kotlin, or to a struct in Swift. Each stored property is a field of the JavaScript object. You don't mark the fields one by one.

<CodeBlocksTable tabs={['MyModule.kt', 'MyModule.swift']}>

```kotlin
@Record
data class SetStringOptions(
  val inputFormat: StringFormat = StringFormat.PLAIN,
  val isSensitive: Boolean = false
)

@ExpoModule("MyModule")
class MyModule : Module() {
  @JS
  suspend fun setStringAsync(content: String, options: SetStringOptions): Boolean {
    // ...
  }
}
```

```swift
@Record
struct SetStringOptions {
  var inputFormat: StringFormat = .plain
  var isSensitive: Bool = false
}

@ExpoModule("MyModule")
public final class MyModule: Module {
  @JS
  func setStringAsync(content: String, options: SetStringOptions) async -> Bool {
    // ...
  }
}
```

</CodeBlocksTable>

A field with a default value is optional: JavaScript can leave it out, and the field gets the default value. With the previous record, JavaScript can call `setStringAsync('text', {})`.

### Required, optional, and nullable fields in Swift

In Swift, the type and the default value of a property set what JavaScript must pass:

```swift
@Record
struct Options {
  var name: String      // Required
  var count: Int = 0    // Optional, because it has a default value
  var note: String?     // Optional and nullable, because its type is optional
}
```

When JavaScript leaves out a required field, the conversion throws `RecordPropertyRequiredException`.

A Swift record has the following rules:

- It is a struct, or a `final` class without an inheritance clause. Declare the protocol conformances of a class in an extension.
- Static, `private`, `fileprivate`, `lazy`, and computed properties aren't fields.
- The macro generates a memberwise initializer that sets every field. So, a `let` field with a default value is a build error.
- A `private` or `fileprivate` stored property needs a default value, unless it is an optional `var`.
- A record converts only from and to JavaScript values. You can't create it from a native dictionary.

If your module builds with a default isolation, for example `-default-isolation MainActor`, a class record or a struct record with a property whose type isn't `Sendable` needs `nonisolated`:

```swift
@Record nonisolated final class Options {
  // ...
}
```

## Unions

<LanguageSupport feature="unions" />

Add `@Union` to an enum whose cases each have one associated value. The enum converts from any of the payload types:

```swift
@Union
enum BinaryInput {
  case bytes(Data)
  case string(String)
}

@JS
func digest(_ input: BinaryInput) -> String {
  switch input {
  case .bytes(let bytes):
    // ...
  case .string(let string):
    // ...
  }
}
```

In TypeScript, `BinaryInput` is `Uint8Array | string`. A union can also be a result, an event payload, a record field, or an element of an optional, an array, or a dictionary.

The conversion tries the cases in the order of the declaration and uses the first case whose payload converts. So, put the most specific case first. For example, a `Double` case before an `Int` case also matches every integer, and the `Int` case is never used. The macro shows a warning for some of these cases, for example a case after a `JavaScriptValue` case. When no case matches, the conversion throws `Exceptions.UnionCaseMismatch`.

To get the payload without a `switch`, use `as(_:)`. It throws `Exceptions.UnionCaseMismatch` when the union holds another case:

```swift
let text = try input.as(String.self)
```

Each case has one associated value, and each payload type is used once. A generic enum, a case without a payload, a case with more than one associated value, and a default value for an associated value are build errors.
