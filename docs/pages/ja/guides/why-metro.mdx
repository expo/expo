title: Metro を使う理由

[Metro](https://metrobundler.dev/) は、Expo と React Native の公式バンドラーです。Expo フレームワークにおける中心的なビルドツールです。バンドラーには無数の意思決定とトレードオフが存在します。このドキュメントでは、Expo が Metro を中心に開発されている主な理由と、それが開発者にとってどのようなメリットをもたらすかを説明します。

## 公式の Meta バンドラー

Metro は、React、React Native、Yoga、Hermes のメンテナーでもある Meta によってメンテナンスされています。アプリストアのあらゆるカテゴリにまたがる、世界最大級のアプリの開発に使われています。

Meta のエンジニアは、40 万以上のソースファイルにまたがる自社のすべてのアプリを、高速かつ信頼性を保ったままバンドルするという明確な要件のもとで、Metro を積極的に開発しています。

Metro を第一級でサポートすることで、Expo の開発者が Meta のツール群との連続性を維持し、新たに登場する機能へ即座にアクセスできるようにしています。具体的には次のような機能があります。

- React Fast Refresh は、2019 年に Metro の機能として [初めて導入されました](https://reactnative.dev/blog/2019/09/18/version-0.61)。React の web コミュニティは、翌年 Webpack 経由でこれを採用しました。
- JavaScript を Hermes バイトコードに変換し、ネイティブの即時起動を実現します。
- [ネットワークと JS のデバッグ](/debugging/tools/#debugging-with-react-native-devtools) を第一級でサポートする React Native DevTools は、Metro と Hermes でのみ利用できます。
- React Compiler は、当初 Metro 互換の Babel プラグインとして展開されました。

Metro に導入が予定されている新機能・今後の機能には、次のようなものがあります。

- Static Hermes を使って Flow コードをネイティブのマシンコードにコンパイルする機能。詳しくは、Tzvetan Mikov による [Static Hermes](https://www.youtube.com/watch?v=GUM64b-gAGg) のトークを参照してください。
- すべてのプラットフォームに対応するユニバーサルな React Server Components による、データフェッチ、ストリーミング、React Suspense、サーバーレンダリング、ビルド時の静的レンダリング。詳しくは、React Conf 2024 での [Universal React Server Components](https://www.youtube.com/watch?v=djhEgxQf3Kw) のトークを参照してください。

Expo チームは Meta と協力して Expo Router 向けに Metro を開発しており、[ファイルベースのルーティング](/develop/app-navigation/)、[web サポート](/ja/guides/customizing-metro/#web-サポート)、[バンドル分割](/ja/guides/customizing-metro/#バンドル分割)、[ツリーシェイキング](/ja/guides/tree-shaking/)、[CSS](/versions/latest/config/metro/#css)、[DOM コンポーネント](/ja/guides/dom-components/)、サーバーコンポーネント、[API routes](/router/web/api-routes/) といった機能を追加しています。

## 大規模環境で実証済み

世界中のほぼすべての React Native アプリが Metro を使用しており、大規模プロジェクト向けに最適化された、実戦で鍛えられたソリューションとなっています。そのため、趣味の開発者から大企業まで、あらゆる規模の開発者に適しています。Metro は大規模な Meta のアプリを扱うために特別に設計されており、そのためデルタバンドリングや [共有リモートキャッシュ](https://metrobundler.dev/docs/caching) といった機能を備えています。

## オンデマンド処理

開発時、Metro はリクエストされるまでプラットフォーム固有の処理を一切行いません。これにより、開発者はサポートするプラットフォームの数によるパフォーマンスコストを払うことなく、大規模プロジェクトに取り組めます。積極的なキャッシュと [非同期ルート](/router/web/async-routes/) を組み合わせることで、開発者は実際に作業しているアプリの部分だけを段階的にバンドルできます。

## 多次元

サーバーコードとクライアントコードをバンドルするために複数のインスタンスを作成する従来のバンドラーとは異なり、Metro はプラットフォームと環境（サーバー、クライアント、DOM コンポーネント）をまたいでリソースの再利用を最大化します。このアーキテクチャは、マルチプラットフォーム開発やサーバー開発に最適です。

## 再利用可能なトランスフォームのメモ化

Metro はインクリメンタルであり、複数のマシンにまたがって使用できるキャッシュ済みのトランスフォームアーティファクトを作成できます。これにより、大規模なチームはリモートビルダーの作業結果を再利用できるようになります。これは Meta ですべての大規模プロジェクトに使われている手法です。

## カスタムランタイムに最適化

他のバンドラーが web ブラウザの静的な仕様を中心に設計されているのに対し、Metro は React Native の柔軟性に最適化されています。これにより、本番環境でのアプリ起動を高速化する Hermes バイトコードコンパイルに必要な、サポート対象言語機能の特定のセットを生成するといった機能が実現します。これは Static Hermes にも拡張される予定であり、ネイティブアプリ向けに静的な型情報をマシンコードへコンパイルするようになります。

## 複数技術にまたがるサポート

Expo は Metro の技術を活用して、[DOM コンポーネント](/ja/guides/dom-components/) のような新しい機能を実現しています。これにより、ネイティブアプリ内の React コンポーネントを、親アプリと同じデフォルト設定を持つ web サイト全体としてオンデマンドに動的バンドルできます。

## ネイティブアセットのエクスポート

最終的な成果物が完全にホストされたアプリとなる従来のバンドラーとは異なり、Metro の設定オプションは、スタンドアロンのアプリバイナリにネイティブアーティファクトとして埋め込むためにバンドルをエクスポートすることをサポートしています。これは、Apple プラットフォームにおける `xcassets` のような OS 固有の最適化を活用します。

## 並行処理

Metro におけるすべての AST 変換は、利用可能なすべてのスレッドにまたがって並行に実行され、ハードウェアの使用を最大化します。

## 他のアプローチとの比較

Metro はユニバーサルなアプリ開発のために設計されていますが、しばしば他の web 専用バンドラーと比較されます。ここでは、いくつかの主要な違いを紹介します。

### ブラウザの ESM 対 バンドリング

Vite のようなバンドラーはブラウザに組み込まれた ESM サポートを活用しますが、このアプローチは中〜大規模になると、数千ものカスケード状のネットワークリクエストによって実際の開発時間が遅くなることがあります。Metro はローカル開発時にバンドリングを行うため、開発結果が本番結果によりいっそう近くなり、React Native のより多いモジュール数にも適しています。

### JavaScript 対 ネイティブ言語

いくつかのバンドラーは、パフォーマンス上の理由からコア部分を Rust で書くことを選んでいますが、これにはコントリビューションやパッチ、開発がより難しくなるといったトレードオフが伴います。Metro は、処理内容に応じて複数の技術を組み合わせて使用しています。

- コアのバンドラーとユーティリティは JS/Flow で書かれています。
- ファイル監視には、デフォルトで JS 製のクローラーが使われ、Watchman（C++）がインストールされている場合はオプションでそれを使用できます。
- AST は、Hermes パーサー（WebAssembly）によって Babel 互換の形式へパースされます。
- AST 変換は Babel によって行われます。これにより、開発者によるカスタマイズ性が最大化されます。
- ミニファイには、ネイティブプラットフォームでは Hermes が、web では Terser（オプションで ESBuild サポートも可能）が使われます。
- CSS のパースとミニファイは、[LightningCSS](https://lightningcss.dev/)（Rust）によって行われます。

このアプローチは Meta やコミュニティのツールと足並みをそろえつつ、開発者にとってデバッグ、プロファイリング、パッチ適用をより簡単にします。
