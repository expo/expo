ビルドキャッシュは、プロジェクトの [フィンガープリント](/versions/latest/sdk/fingerprint/) に基づいてビルドをリモートでキャッシュすることで、`npx expo run:[android|ios]` を高速化する機能です。
`npx expo run:[android|ios]` を実行すると、一致するフィンガープリントを持つビルドが存在するかどうかを確認し、存在する場合は再度コンパイルする代わりにそのビルドをダウンロードして起動します。存在しない場合は、プロジェクトは通常どおりコンパイルされ、生成されたバイナリは今後の実行のためにリモートキャッシュにアップロードされます。

## ビルドプロバイダーとして EAS を使う

EAS Build プロバイダープラグインを使うには、まず `eas-build-cache-provider` パッケージを開発用の依存関係としてインストールします。

<Tabs>

<Tab label="macOS/Linux">

<Terminal
  cmd={{
    npm: ['$ npx expo install eas-build-cache-provider --dev'],
    yarn: ['$ yarn expo install eas-build-cache-provider --dev'],
    pnpm: ['$ pnpm expo install eas-build-cache-provider --dev'],
    bun: ['$ bun expo install eas-build-cache-provider --dev'],
  }}
/>

</Tab>

<Tab label="Windows">

<Terminal
  cmd={{
    npm: ['$ npx expo install eas-build-cache-provider "--" --dev'],
    yarn: ['$ yarn expo install eas-build-cache-provider "--" --dev'],
    pnpm: ['$ pnpm expo install eas-build-cache-provider "--" --dev'],
    bun: ['$ bun expo install eas-build-cache-provider "--" --dev'],
  }}
/>

</Tab>

</Tabs>

次に、**app.json** を更新して `buildCacheProvider` プロパティとそのプロバイダーを含めます。

```json app.json
{
  "expo": {
    "buildCacheProvider": "eas"
    /* @hide ... */ /* @end */
  }
}
```

以下のメソッドを実装するプラグインをエクスポートすることで、独自のキャッシュプロバイダーを自作できます。

```ts
type BuildCacheProviderPlugin<T = any> = {
  /**
   * Try to fetch an existing build. Return its URL or null if missing.
   */
  resolveBuildCache(props: ResolveBuildCacheProps, options: T): Promise<string | null>;

  /**
   * Upload a new build binary. Return its URL or null on failure.
   */
  uploadBuildCache(props: UploadBuildCacheProps, options: T): Promise<string | null>;

  /**
   * (Optional) Customize the fingerprint hash algorithm.
   */
  calculateFingerprintHash?: (
    props: CalculateFingerprintHashProps,
    options: T
  ) => Promise<string | null>;
};

type ResolveBuildCacheProps = {
  projectRoot: string;
  platform: 'android' | 'ios';
  runOptions: RunOptions;
  fingerprintHash: string;
};
type UploadBuildCacheProps = {
  projectRoot: string;
  buildPath: string;
  runOptions: RunOptions;
  fingerprintHash: string;
  platform: 'android' | 'ios';
};
type CalculateFingerprintHashProps = {
  projectRoot: string;
  platform: 'android' | 'ios';
  runOptions: RunOptions;
};
```

GitHub Releases を使ってビルドをキャッシュするリファレンス実装は、[Build Cache Provider Example](https://github.com/expo/examples/tree/master/with-github-remote-build-cache-provider) にあります。

## 制限事項

ビルドキャッシュプロバイダーが参照されるのは、ローカルの `npx expo run:[android|ios]` コマンドのみです。`eas build` によってトリガーされるビルドには影響しません。これらは常に新しいアーティファクトを生成し、キャッシュプロバイダープラグインを呼び出すことはありません。

また、一部のローカルビルドはスキップされます。

- **iOS の実機ビルド。** 実機向けのビルドは、そのプロビジョニングプロファイルに一致するデバイスでのみ有効なため、マシンやデバイスをまたいで再利用するのは安全ではありません。そのため `npx expo run:ios` は、対象が実機の場合、キャッシュの参照とビルド後のアップロードの両方をスキップします。キャッシュの対象になるのは iOS シミュレーターのビルドのみです。

**eas.json** で `appVersionSource: "remote"` を使っている場合、`versionCode`（Android）と `buildNumber`（iOS）はプロジェクトのソースではなく EAS サーバー上にあるため、フィンガープリントの入力には含まれない点に注意してください。通常の開発の反復ではこれで問題ありません。ローカルの `npx expo run:*` の実行はこれらの値を自動的にインクリメントしませんが、キャッシュされたアーティファクトには、最初にビルドされたときに埋め込まれたビルド番号がそのまま残ることに注意してください。

## カスタムビルドプロバイダーを作成する

まず、プロバイダープラグインを TypeScript で書くための **provider** ディレクトリを作成し、プロジェクトのルートに、プラグインのエントリーポイントとなる **provider.plugin.js** ファイルを追加します。

<Step label="1">
### `provider/tsconfig.json` ファイルを作成する

```json provider/tsconfig.json
{
  "extends": "expo-module-scripts/tsconfig.plugin",
  "compilerOptions": {
    "outDir": "build",
    "rootDir": "src"
  },
  "include": ["./src"],
  "exclude": ["**/__mocks__/*", "**/__tests__/*"]
}
```

</Step>

<Step label="2">
### プラグイン用の `provider/src/index.ts` ファイルを作成する

```ts provider/src/index.ts
import { type BuildCacheProviderPlugin } from '@expo/config';

const plugin: BuildCacheProviderPlugin = {
  resolveBuildCache: async () => {
    console.log('Searching for remote builds...');
    return null;
  },
  uploadBuildCache: async () => {
    console.log('Uploading build to remote...');
    return null;
  },
};

export default plugin;
```

</Step>

<Step label="3">
### ルートディレクトリに `provider.plugin.js` ファイルを作成する

```js provider.plugin.js
// This file configures the entry file for your plugin.
module.exports = require('./provider/build');
```

</Step>

<Step label="4">
### プロバイダープラグインをビルドする

プロジェクトのルートで `npm run build provider` を実行し、TypeScript コンパイラをウォッチモードで起動します。

</Step>

<Step label="5">
### `example/app.json` ファイルに次の行を追加して、サンプルプロジェクトがプラグインを使うように設定する

```json example/app.json
{
  "expo": {
    /* @hide ... */ /* @end */
    "buildCacheProvider": {
      "plugin": "./provider.plugin.js"
    }
  }
}
```

</Step>

<Step label="6">
### プロバイダーをテストする
**example** ディレクトリ内で `npx expo run` コマンドを実行すると、ログにプラグインの console 文が表示されるはずです。

<Terminal
  cmd={[
    '# Navigate to the example directory',
    '$ cd example',
    '',
    '# Run the example on Android',
    '$ npx expo run:android',
    '',
    '# Run the example on iOS',
    '$ npx expo run:ios',
  ]}
/>

これで完了です！ ビルドを高速化するリモートビルドキャッシュプロバイダーができました。

</Step>

### カスタムオプションを渡す

プラグインにカスタムオプションを注入するには `options` フィールドを使えます。これはカスタム関数の第 2 引数として渡されます。そのためには、以下のように **example/app.json** の `buildCacheProvider` フィールドを変更します。

```json example/app.json
{
  "expo": {
    /* @hide ... */ /* @end */
    "buildCacheProvider": {
      "plugin": "./provider.plugin.js",
      "options": {
        "myCustomKey": "XXX-XXX-XXX"
      }
    }
  }
}
```
