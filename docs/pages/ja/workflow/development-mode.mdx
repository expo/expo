プロジェクトは常に**開発**モードか**本番**モードのいずれかで実行されます。デフォルトでは、`npx expo start` でプロジェクトをローカルで実行すると開発モードで動作します。一方、（`eas update` で）公開されたプロジェクトや、あらゆるスタンドアロンアプリは本番モードで動作します。

**開発モード**には便利な警告が含まれ、開発とデバッグを容易にするツールにアクセスできます。**本番モード**では [コードが圧縮され](/ja/guides/customizing-metro/#圧縮)、エンドユーザーのデバイスでのアプリのパフォーマンスをより正確に表しています。それぞれのモードについて詳しく見ていき、モード同士をどう切り替えられるかを学びましょう。

## 開発モード

React Native には、開発に役立つツールがいくつか含まれています。Chrome でのリモート JavaScript デバッグ、ライブリロード、ホットリロード、そして Chrome で使い慣れたインスペクターに似たエレメントインスペクターです。これらのツールの使い方を確認したい場合は、[デバッグ](/debugging/runtime-issues/) を参照してください。

開発モードでは、アプリの実行中に検証を行って警告を表示します。たとえば、非推奨のプロパティを使っている場合や、コンポーネントに必須のプロパティを渡し忘れた場合などです。以下の動画は、Android エミュレーターと iOS シミュレーターの両方でエレメントインスペクターとパフォーマンスモニターが動作している様子を示しています。

> **warning** **これには代償があります。開発モードではアプリの動作が遅くなります。** <br /> Expo CLI でオン・オフを切り替えられます。詳しくは [本番モード](#本番モード) を参照してください。切り替えたら、変更を反映させるためにアプリを閉じて再度開いてください。**アプリのパフォーマンスをテストするときは、必ず開発モードを無効にしてください**。

### 開発者メニューを表示する

このメニューを使うと、開発とデバッグを大幅に楽にする多数の機能にアクセスできます。Android と iOS での開き方について詳しくは、[開発者メニュー](/debugging/tools/#developer-menu) を参照してください。

## 本番モード

本番モードは主に次の 2 つの場面で役立ちます。

- アプリのパフォーマンスをテストする。開発モードではアプリの動作がかなり遅くなるためです。
- 本番でしか現れないバグを見つける。

プロジェクトがエンドユーザーのデバイスでどのように動作するかを再現する最も簡単な方法は、次のコマンドを使うことです。

<Terminal
  cmd={{
    npm: ['$ npx expo start --no-dev --minify'],
    yarn: ['$ yarn expo start --no-dev --minify'],
    pnpm: ['$ pnpm expo start --no-dev --minify'],
    bun: ['$ bun expo start --no-dev --minify'],
  }}
/>

このコマンドは、アプリの JavaScript を本番モードで実行します（これにより、Metro バンドラーはいくつかの設定の中でも特に `__DEV__` 環境変数を `false` に設定します）。`--minify` フラグはアプリを圧縮します。このフラグは、コメントや整形、未使用のコードといった不要なデータも取り除きます。スタンドアロンアプリでエラーやクラッシュが発生している場合、このコマンドでプロジェクトを実行すると、根本原因を見つける時間を大幅に短縮できます。

> **info** 本番モードでは、コンソールログは Expo CLI のターミナルに表示されません。デバイス上のネイティブログを通じてログにアクセスする方法については、[本番モードでコンソールログを表示する](/ja/workflow/logging/#本番モードでコンソールログを表示する) を参照してください。

アプリを本番用に完全にコンパイルするには、[Android のコンパイル](/more/expo-cli/#compiling-android) と [iOS のコンパイル](/more/expo-cli/#compiling-ios) を参照してください。
