Expo Router records performance marks for navigation events. You can observe these marks and send their details to your analytics solution. This is useful when you need to track when a screen becomes focused, including when a previously mounted screen regains focus. If you only need to track URL changes, see [screen tracking for analytics](/router/reference/screen-tracking/).

## Track focused screens

Enable the experimental performance integration before the root layout mounts. Observe `expo-router:page-focused` marks and send their details to your provider:

```tsx src/app/_layout.tsx
import { useEffect } from 'react';
import {
  Slot,
  unstable_enablePerformanceIntegration,
  unstable_PerformanceObserver,
  type RouterPageFocusedMark,
} from 'expo-router';

unstable_enablePerformanceIntegration();

export default function Layout() {
  useEffect(() => {
    const observer = new unstable_PerformanceObserver(list => {
      for (const entry of list.getEntriesByName('expo-router:page-focused')) {
        // The mark name determines the type of its detail.
        const { detail } = entry as RouterPageFocusedMark;
        analytics.track({
          pathname: detail.pathname,
          params: detail.params,
          screenId: detail.screenId,
        });
      }
    });

    observer.observe({ type: 'mark', buffered: true });
    return () => observer.disconnect();
  }, []);

  return <Slot />;
}
```

Replace `analytics.track` with your provider's event method. The `buffered` option includes marks recorded before the observer starts, including the initial screen. A preloaded screen does not produce a focus mark until the user navigates to it. Each mark also has a `startTime` you can send if your provider accepts a timestamp.

Expo Router also records `expo-router:page-preloaded`, `expo-router:page-blurred`, `expo-router:page-removed`, and `expo-router:action-dispatched` marks. Observe these names if your solution needs more navigation events. This API is experimental and its names may change.
