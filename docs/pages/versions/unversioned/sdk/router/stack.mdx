An Expo Router API that provides Stack navigator, toolbar, and screen components.

> See the [Expo Router](./index) reference for installation and configuration.

## Usage

```tsx
import { Stack } from 'expo-router';

export default function Layout() {
  return <Stack />;
}
```

### Required screens below a screen

> **info** The `unstable_` prefix means that the behavior of this prop can change slightly between releases. The prop is safe to use. A later release will not remove it.

A deep link or a push from another screen can open a screen with nothing below it in the stack. Then the back action leaves the stack. Use the `unstable_requiredScreensBelow` prop of `Stack.Screen` in a layout to list the screens that must be below that screen.

```tsx app/_layout.tsx
import { Stack } from 'expo-router';

export default function Layout() {
  return (
    <Stack>
      <Stack.Screen name="index" />
      <Stack.Screen name="[id]" />
      <Stack.Screen
        name="[id]/comments"
        unstable_requiredScreensBelow={[
          'index',
          { name: '[id]', params: { id: '1' } },
        ]}
      />
    </Stack>
  );
}
```

Each entry is a screen name from the same `Stack`, such as `'[id]'`. It is not an href, such as `'/1'`.

When the user opens **/42/comments**, the stack contains `index`, `[id]` with `id` set to `1`, and `[id]/comments` with `id` set to `42`.

The stack adds the required screens when a deep link or a navigation opens the screen. A prop change or a back action adds nothing. Required screens go directly below the screen, in the listed order. If a route with the same name and path params is already below, the stack skips it.

When you list a screen by name, it gets the matching path params of the opened screen. For example, with `'[id]'` instead of the object above, **/42/comments** adds `[id]` with `id` set to `42`. An object entry uses only its own `params`.

The stack does not follow the required screens of a screen that it adds. For example, if `[id]/comments` lists only `'[id]'`, and `[id]` lists `'index'`, a deep link to **/42/comments** gives a stack with only `[id]` and `[id]/comments`. List every screen that you need below.

`router.canGoBack()` returns the previous result during the first render of the screen. The stack adds the required screens to the navigation state after that render.

The prop works only on a `Stack.Screen` in a layout. It has no effect on a `Stack.Screen` in a page.
