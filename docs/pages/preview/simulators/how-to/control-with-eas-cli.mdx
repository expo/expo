Use `eas simulator:control` for direct actions on a running iOS Simulator. It connects through the session's preview server, so it works with any iOS session type that exposes that server, including `web-preview-only`.

For accessibility snapshots and actions that select elements by their labels, use [agent-device, Argent, or Appium](/preview/simulators/how-to/drive-the-device/). Direct controls do not provide an accessibility tree. Android sessions use those controllers instead.

## Select the session and discover its actions

[Install or update EAS CLI](/eas/cli/), then run commands from the linked project. Pass the ID of a running iOS session:

<Terminal
  cmd={[
    '$ eas simulator:get --id <session-id> --json',
    '$ eas simulator:control --id <session-id>',
    '$ eas simulator:control --id <session-id> --json',
  ]}
/>

Check that the session status is `IN_PROGRESS`. The control command without an action lists the actions that its serve-sim version supports. With `--json`, it returns their descriptions, argument order, accepted properties, and file upload or download behavior. Read this catalog before you run an unfamiliar action. Older sessions can have a different catalog; updating EAS CLI does not update a running session.

If you omit `--id`, the command uses the session ID from **.env.eas-simulator** or the shell environment. Pass `--id` when you have more than one session. EAS CLI selects the device that the session streams. You do not need to copy its device identifier or preview token.

A private preview link works with direct controls. You do not need `--public-link`. Keep credentials out of the command.

## Change settings and app permissions

<Terminal
  cmd={[
    '$ eas simulator:control appearance.set dark --id <session-id>',
    '$ eas simulator:control hardwareKeyboard.set off --id <session-id>',
    '$ eas simulator:control reduceMotion.set on --id <session-id>',
    '$ eas simulator:control permissions.set grant camera com.example.app --id <session-id>',
  ]}
/>

Use the matching `get` action, such as `appearance.get`, to read a setting. A permission change applies to the app whose bundle identifier you pass.

You do not need to restart the app to change its permission state. Some frameworks cache their status until relaunch. Read the Simulator's service authorization after a change:

<Terminal
  cmd={['$ eas simulator:control permissions.list com.example.app --id <session-id> --json']}
/>

On iOS 27.1, an app that has never requested notification permission may still need its normal request flow after a grant. Call `UNUserNotificationCenter.requestAuthorization` from the app, or `Notifications.requestPermissionsAsync()` with [expo-notifications](/versions/latest/sdk/notifications/). This initializes notification capabilities; restarting alone does not. Service authorization does not confirm notification delivery.

## Tap and enter text

Tap coordinates range from 0 to 1, relative to the screen. This example taps the center:

<Terminal
  cmd={[
    '$ eas simulator:control tap 0.5 0.5 --id <session-id>',
    '$ eas simulator:control type "hello@example.com" --id <session-id>',
  ]}
/>

`type` sends American Standard Code for Information Interchange (ASCII) text to the focused field using a United States keyboard layout. For Unicode text, paste through the simulator clipboard:

<Terminal
  cmd={[
    '$ eas simulator:control clipboard.write "Hello, 世界" --id <session-id>',
    '$ eas simulator:control clipboard.paste --id <session-id>',
  ]}
/>

Writing the clipboard does not paste. Focus the intended field before pasting. Keep passwords and access tokens out of command arguments and shell history.

## Restart an installed app

Use `app.launch` to restart an installed app. Replace `com.example.app` with the installed build's bundle identifier, which can differ from your project's app config:

<Terminal cmd={['$ eas simulator:control app.launch com.example.app --id <session-id>']} />

To pass launch arguments, use a JSON array of strings. These flags belong to your app; your app defines what they do:

<Terminal
  cmd={[
    '$ eas simulator:control app.launch com.example.app \\',
    '  \'launchArgs=["-UITestMode","1","-Greeting","Hello, world"]\' \\',
    '  --id <session-id>',
  ]}
  cmdCopy={`eas simulator:control app.launch com.example.app 'launchArgs=["-UITestMode","1","-Greeting","Hello, world"]' --id <session-id>`}
/>

Use double quotes inside the JSON and single quotes around the shell argument. Every item must be a string, including values such as `"1"`. Omitting `launchArgs` or passing `'launchArgs=[]'` launches without custom arguments. It does not reuse or merge arguments from a previous launch or session startup.

Add `openUrl` to open a deep link after restarting. Quote the URL so your shell preserves query parameters such as `&`:

<Terminal
  cmd={[
    '$ eas simulator:control app.launch com.example.app \\',
    '  \'launchArgs=["-UITestMode","1"]\' \\',
    "  'openUrl=myapp://profile/42?tab=activity&source=cli' \\",
    '  --id <session-id>',
  ]}
  cmdCopy={`eas simulator:control app.launch com.example.app 'launchArgs=["-UITestMode","1"]' 'openUrl=myapp://profile/42?tab=activity&source=cli' --id <session-id>`}
/>

Launch arguments are optional. When you omit them, use `openUrl=` so the URL does not fill the `launchArgs` position:

<Terminal
  cmd={[
    '$ eas simulator:control app.launch com.example.app \\',
    "  'openUrl=myapp://profile/42?tab=activity&source=cli' \\",
    '  --id <session-id>',
  ]}
  cmdCopy={`eas simulator:control app.launch com.example.app 'openUrl=myapp://profile/42?tab=activity&source=cli' --id <session-id>`}
/>

The app starts before the URL opens. If opening the URL fails, the app can stay running with the new arguments. Inspect the device before retrying.

To send a deep link without restarting the app, use `app.openUrl`:

<Terminal
  cmd={[
    '$ eas simulator:control app.openUrl com.example.app \\',
    "  'myapp://profile/42?tab=activity&source=cli' --id <session-id>",
  ]}
  cmdCopy={`eas simulator:control app.openUrl com.example.app 'myapp://profile/42?tab=activity&source=cli' --id <session-id>`}
/>

A custom scheme URL may show a confirmation prompt. Check that the app shows the expected screen before sending more input.

To install an app during startup, use `--build-id` or `--application-archive-url`. To install a local **.app** folder, use the controller's install command. See [Install an app on a remote Android Emulator or iOS Simulator](/preview/simulators/how-to/install-your-app/). The direct control file upload accepts files, not folders.

Run commands that change the device one at a time. If a command times out, inspect the device before retrying: the action might already have run.
