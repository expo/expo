A new EAS Simulator session starts with a blank device. To put your app on it, give `eas simulator:start` an **application source**. EAS then downloads, installs, and launches the app before the session becomes ready. You can also start a blank session and install a local build through the controller.

## Choose an application source

| Application source         | Start flag                        | Use it for                                                                                                                                    |
| -------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| EAS Build ID               | `--build-id <id>`                 | One specific EAS Build.                                                                                                                       |
| EAS Build fingerprint      | `--build-fingerprint <hash>`      | The most recent finished, non-expired build with the fingerprint hash that you pass.                                                          |
| Application archive URL    | `--application-archive-url <url>` | A build that another system made and published to a URL.                                                                                      |
| Expo Go                    | `--expo-go`                       | A project that you can test in Expo Go. See [Test your project in Expo Go on a remote simulator](/preview/eas-simulator/works-with/expo-go/). |
| Local build, after startup | No start flag                     | A **.app** or **.apk** on your computer. See [Install a local build](#install-a-local-build).                                                 |

The four start flags are mutually exclusive. Pass at most one of them. A session without an application source starts with a blank device.

## Build a simulator-compatible app

A remote device is a simulator or an emulator, not a physical phone. Build for that target:

| Platform | Required build                                                                                     | Fails to install                     |
| -------- | -------------------------------------------------------------------------------------------------- | ------------------------------------ |
| Android  | An **.apk**. With EAS Build, [build an APK](/build-reference/apk/).                                | An **.aab**.                         |
| iOS      | An iOS Simulator build. With EAS Build, set [`ios.simulator: true`](/build-reference/simulators/). | A device build, such as an **.ipa**. |

This EAS Build profile creates an installable build for both platforms:

```json eas.json
{
  "build": {
    "remote-device": {
      "ios": {
        "simulator": true
      },
      "android": {
        "buildType": "apk"
      }
    }
  }
}
```

iOS Simulator builds are not signed, so EAS Build does not ask for credentials. For more information, see [Which build to install on EAS Simulator](/preview/eas-simulator/how-it-works/builds-and-bundles/).

## Install an EAS Build

Create the build **before** you start the session. A build can take longer than the maximum duration or idle limit of a session:

<Terminal cmd={['$ eas build --platform ios --profile remote-device --non-interactive']} />

Record the build ID from the output. To find an existing iOS Simulator build, list the finished builds:

<Terminal
  cmd={['$ eas build:list --platform ios --simulator --status finished --json --non-interactive']}
/>

For Android, leave out `--simulator`, because the flag works only with `--platform ios`. Pick an APK build from the list:

<Terminal
  cmd={['$ eas build:list --platform android --status finished --json --non-interactive']}
/>

Then pass the build ID to the start command:

<Terminal
  cmd={[
    '$ eas simulator:start --platform ios --type agent-device --build-id <build-id> --name "Release build review" --non-interactive',
  ]}
/>

For Android, use `--platform android` in the `eas build` and `eas simulator:start` commands. The Android build must be an APK.

## Install the build that matches a fingerprint

A [fingerprint](/versions/latest/sdk/fingerprint/) is a hash of the native parts of your project. `eas simulator:start` does not calculate the fingerprint for you. To get the hash for your current project, run `eas fingerprint:generate` with the build profile that you use for remote device builds:

<Terminal
  cmd={[
    '$ eas fingerprint:generate --platform ios --build-profile remote-device --non-interactive',
  ]}
/>

The command prints `Fingerprint generated: <hash>`. Pass the hash to install the most recent finished, non-expired build with that fingerprint. On iOS, the build must target the iOS Simulator:

<Terminal
  cmd={[
    '$ eas simulator:start --platform ios --type agent-device --build-fingerprint <fingerprint-hash> --name "Fingerprint build review" --non-interactive',
  ]}
/>

Use a fingerprint when any build with that fingerprint hash is acceptable, and `--build-id` when you need one specific build. On Android, EAS can select a build of any distribution type, so use a build profile that creates an APK.

## Install from an application archive URL

Pass an HTTP or HTTPS URL that returns the file directly. The remote device downloads the file one time, when the session starts:

<Terminal
  cmd={[
    '$ eas simulator:start --platform ios --type agent-device --application-archive-url "https://example.com/MyApp.tar.gz" --name "Archive review" --non-interactive',
  ]}
/>

For iOS, use a gzip tarball (**.tar.gz** or **.tgz**) that contains the **.app** directory, or the contents of the **.app** bundle at its root. A **.zip** or **.app.zip** archive does not install. For Android, use the URL of an **.apk**. An **.aab** does not install. A signed URL works while it is valid.

## Pass launch arguments and open a URL

When you use an application source, you can also pass launch arguments and a URL to open after the app launches:

<Terminal
  cmdCopy={`eas simulator:start --platform ios --type agent-device --build-id <build-id> --launch-arg "-UITestMode" --launch-arg "1" --open-url "myapp://profile/42" --name "Profile screen review" --non-interactive`}
  cmd={[
    '$ eas simulator:start --platform ios --type agent-device --build-id <build-id> \\',
    '    --launch-arg "-UITestMode" --launch-arg "1" \\',
    '    --open-url "myapp://profile/42" \\',
    '    --name "Profile screen review" --non-interactive',
  ]}
/>

Repeat `--launch-arg` for each argument. EAS passes the arguments in the same order. `--launch-arg` and `--open-url` require an application source. Without one, the command fails with `Launch options require an application source`.

In an iOS agent-device or Argent session, EAS tries to approve the custom URL scheme first. Then the system **Open in** dialog does not appear. In other session types, or if the approval fails, the dialog can appear. Accept it in the browser preview or with the controller.

## Install a local build

To install a build that is on your computer, start a blank session. Then upload the build through the controller:

<Tabs>

<Tab label="agent-device">

<Terminal
  cmd={[
    '$ eas simulator:start --platform ios --type agent-device --name "Local build review" --non-interactive',
    '$ eas simulator:exec npx agent-device@latest install com.example.app ./path/to/MyApp.app --platform ios',
    '$ eas simulator:exec npx agent-device@latest open com.example.app --platform ios',
  ]}
/>

For Android, use the Android package name, the APK path, and `--platform android`.

</Tab>

<Tab label="Argent">

<Terminal
  cmd={[
    '$ eas simulator:start --platform ios --type argent --name "Local build review" --non-interactive',
    '$ eas simulator:exec argent run list-devices',
    '$ eas simulator:exec argent run reinstall-app --udid <udid> --bundleId com.example.app --appPath ./MyApp.app',
  ]}
/>

Use the unique device identifier (UDID) of the booted device from `list-devices`. The `reinstall-app` tool uploads the local bundle to the remote session. This requires Argent 0.16.0 or later.

</Tab>

</Tabs>

A local upload takes longer for a large build. When the build is at a URL, the remote device can download it instead:

<Terminal
  cmd={[
    '$ eas simulator:exec npx agent-device@latest install-from-source "https://expo.dev/artifacts/eas/<artifact>.tar.gz" --platform ios',
  ]}
/>

## Find the app identifier

Controller commands use the app identifier. For an Expo project, read it from the resolved app config:

<Terminal cmd={['$ npx expo config --json']} />

Use `android.package` for Android and `ios.bundleIdentifier` for iOS. For other toolchains, use the package name or bundle identifier that your build system assigns.

## Common questions

<FAQ>

<Collapsible summary="Why does the app show old code?">

A release build contains the JavaScript from the time of the build. Changes to your source files do not update it. Create a new build, use a build with a matching fingerprint, or use a development build with Metro. See [Use Fast Refresh with Metro on a remote simulator](/preview/eas-simulator/how-to/iterate-on-your-code/).

</Collapsible>

<Collapsible summary="Can I install an app with an Appium session?">

Yes. The start flags install and launch the app for all session types, including `appium`. See [Run Appium tests on a remote Android Emulator or iOS Simulator](/preview/eas-simulator/works-with/appium/).

</Collapsible>

</FAQ>
