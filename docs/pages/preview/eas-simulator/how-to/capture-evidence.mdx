Evidence shows what the app did on the remote device. Use a **screenshot** for a still state, a **recording** for motion, and **session activity** for the list of actions that a person or an agent did. EAS also keeps **session artifacts**, such as recordings and screenshots, that you can download from EAS CLI or from the session page on expo.dev.

## Choose the evidence

| Question                                           | Evidence                                     |
| -------------------------------------------------- | -------------------------------------------- |
| Does the screen look correct?                      | Screenshot                                   |
| Does an animation, gesture, or transition work?    | Screen recording                             |
| Which actions did the agent do, and in what order? | Session activity from `eas simulator:events` |
| What did the app print?                            | Device logs from the controller              |

## Take a screenshot

Open the app first. agent-device needs an open app session before it can take a screenshot:

<Terminal
  cmd={[
    '$ eas simulator:exec npx agent-device@latest open com.example.app --platform ios',
    '$ eas simulator:exec npx agent-device@latest screenshot ./artifacts/home.png',
  ]}
/>

The screenshot downloads to the computer that runs the command. Take the screenshot only after the correct build is on screen. A release build shows the code from build time. See [Builds and bundles](/preview/eas-simulator/how-it-works/builds-and-bundles/).

The status bar of the iOS Simulator shows `9:41` by default. This time does not mean that the screenshot is old.

### Control the screenshot size

agent-device takes full-resolution screenshots by default. A full-resolution image uses more tokens when an agent reads it. From agent-device 0.20.6, pass `--scale` with a value from 0.01 to 1 to make the image smaller:

<Terminal
  cmd={['$ eas simulator:exec npx agent-device@latest screenshot ./artifacts/home.png --scale 0.5']}
/>

Keep the full resolution for an image that you compare pixel by pixel with another image.

## Record the screen

<Terminal
  cmd={[
    '$ eas simulator:exec npx agent-device@latest record start',
    '# Use the app',
    '$ eas simulator:exec npx agent-device@latest record stop ./artifacts/flow.mp4',
  ]}
/>

Recordings capture about 30 frames each second. This rate shows visible jank, but it cannot prove or disprove a short frame drop on a 60 Hz or 120 Hz display.

With Argent, use the `screen-recording-start` and `screen-recording-stop` tools. Argent removes frames that do not change by default, so turn off that option when you measure timing. Argent recordings on EAS Simulator include an Argent watermark.

### Recover a recording that did not download

If the controller does not download a recording, EAS can still have it as a session artifact. Get the session with its ID, and find the recording in the `artifacts` array:

<Terminal cmd={['$ eas simulator:get --id <session-id> --json --non-interactive']} />

Download the file from its `downloadUrl`:

<Terminal
  cmd={[`$ curl --fail --location --max-time 600 --output ./capture.mp4 '<download-url>'`]}
/>

The download link redirects to a signed URL that is valid for one hour. If the URL expires, get the session again for a new URL. You can get artifacts after the session stops.

## Read session activity

Sessions that use agent-device or Argent record each controller action. Show the activity so far:

<Terminal cmd={['$ eas simulator:events']} />

Follow new activity in another terminal while you or an agent use the device:

<Terminal cmd={['$ eas simulator:events --follow']} />

Use `--json` to get the raw event records for a script or an agent. You cannot use `--json` together with `--follow`. Session activity shows controller actions. It does not show the logs of your app.

## Read device logs

agent-device has a `logs` command that collects device logs. Logging is off by default. Open a log window for one reproduction instead of collecting all device logs. Read the version-matched help for the syntax:

<Terminal cmd={['$ eas simulator:exec npx agent-device@latest help debugging']} />

## Find artifacts on expo.dev

The session page on expo.dev shows the evidence that EAS stores for the session:

| Section              | Content                                                                                                                                         |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Preview or recording | The live iOS preview while the session runs. After it ends, the recording player.                                                               |
| Session activity     | The recorded controller actions.                                                                                                                |
| Artifacts            | Files grouped as screenshots, screen recordings, traces, performance metrics, native profiles, React profiles, session events, and other files. |
| Logs                 | The logs of the job that ran the session. This section starts collapsed.                                                                        |

Screen recordings on the session page are available for iOS sessions.

EAS keeps logs and artifacts for 30 days after the session is created. Download the files that you want to keep. See [Security and data](/preview/eas-simulator/reference/security-and-data/).

## Common questions

### Why does the screenshot command say that there is no active session?

agent-device needs an open app. Run `open <app-id>` before `screenshot`. If the start command launched the app with `--open-url`, attach without a relaunch: `open <app-id> --foreground --platform ios`.

### How do I prove that the screenshot came from the remote device?

Confirm that `eas simulator:get --json` returns the session ID that the start command printed. See [Agent targeting](/preview/eas-simulator/how-it-works/agent-targeting/).

### Can other people see my artifacts?

People with access to the project can see the session page. An artifact download link works without an Expo login, so share it only with people who should see the file.
