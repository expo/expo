A reviewer can test a pull request in the browser without a local build. Create an iOS Simulator build for the pull request, then add a **create session link** to the pull request. When the reviewer opens the link, EAS starts an iOS Simulator session with the build and shows the browser preview.

## Add a review link to a pull request

<Step label="1">

### Create an iOS Simulator build for the pull request

Use a build profile with `ios.simulator: true`, and create the build in CI or with EAS Workflows:

<Terminal cmd={['$ eas build --platform ios --profile remote-device --non-interactive']} />

Record the build ID. For a profile example, see [Install your app](/preview/eas-simulator/how-to/install-your-app/#build-a-simulator-compatible-app).

</Step>

<Step label="2">

### Build the link

Use the account name, the project slug, and the build ID. Add a name that includes the pull request number:

```text
https://expo.dev/accounts/acme/projects/my-app/simulator-sessions/create?buildId=BUILD_UUID&name=PR%201234%20review
```

To use the most recent build that matches the native code of the pull request, use `buildFingerprint` and `platform=ios` instead of `buildId`. For all parameters, see [Start a session from a link](/preview/eas-simulator/how-to/hand-off-a-session/#start-a-session-from-a-link).

</Step>

<Step label="3">

### Post the link

Add the link to the pull request description or to a comment from your CI system. Tell reviewers that each click starts a new session.

</Step>

## What the reviewer sees

1. The reviewer opens the link and signs in to an Expo account that can access the project.
2. expo.dev validates the build and starts the session. This can take about a minute.
3. expo.dev opens the browser preview in fullscreen mode. The reviewer uses the app in the browser.
4. When the reviewer finishes, they stop the session from its page on expo.dev.

To return to the same session, the reviewer opens it from the project's **Simulator sessions** page. Opening the link again starts a new session.

## Let an agent review the change

An agent can also test the pull request and post evidence. Ask the agent to use the [EAS Simulator skill](/preview/eas-simulator/how-to/verify-a-change-with-an-agent/), start a session with the pull request build, run the changed flow, and attach screenshots or a recording. For an EAS Workflows example, see Callstack's [agent-device EAS Workflow template](https://github.com/callstackincubator/eas-agent-device/blob/main/.eas/workflows/agent-qa-mobile.yml).

## Common questions

### Can reviewers test an Android build from the link?

No. Create session links currently support iOS. For Android, start a session with EAS CLI or the REST API.

### Does the link work for people outside my team?

The person must sign in to an Expo account that can access the project. To start a session, the account needs the Developer role or higher.

### How do I limit usage from review links?

Each click on the link starts a session that runs until it stops. Create session links do not set a custom duration, so the session gets the default maximum duration for your plan. Ask reviewers to stop the session when they finish. See [Usage and billing](/preview/eas-simulator/reference/usage-and-billing/).
