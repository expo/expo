> **important** **EAS Simulator is a limited-access preview.** It is not included with paid or free plans and is currently available only to select partners. [Join the waitlist](https://expo.dev/services/simulators) if you are interested in trying it.

Access to an EAS Simulator session comes from two sources: your Expo account role and secret values that the session creates. Your role controls who can create, read, and stop sessions. The secret values, such as controller tokens and preview tokens, let a program or a browser reach the running device. Anyone who has a secret value can use what it unlocks, so treat each one as a password.

This page explains the model. For the exact values and limits, see [Security and data](/preview/eas-simulator/reference/security-and-data/).

## Trust boundaries

| Boundary                 | What controls access                                  | Who has access                                           |
| ------------------------ | ----------------------------------------------------- | -------------------------------------------------------- |
| Create and stop sessions | Expo account role                                     | Developer, Release Manager, Admin, and Owner roles       |
| Read a session           | Expo account role                                     | All roles that can view the project, including View Only |
| Control the device       | Controller token in the connection details            | Anyone who has the token while the session runs          |
| See the browser preview  | Preview URL and, when the preview is gated, its token | Anyone who has the URL                                   |
| Download an artifact     | Random download URL                                   | Anyone who has the URL                                   |
| Reach your Metro server  | Public tunnel URL                                     | Anyone who has the URL while the tunnel runs             |
| Reach your local network | `--egress-allow` list                                 | Only the destinations that you list                      |

## Account permissions

EAS checks your role on the account that owns the project:

- To create, stop, or delete a session, you need the Developer role or higher.
- To read a session, you need access to view the project.

A read of a session in progress returns its connection details. Because of this, a person who can view the project can get the controller tokens of a running session.

For CI and services, use a [robot user](/accounts/programmatic-access/#robot-users-and-access-tokens) with the Developer role. Store its token in a secret store.

## Controller tokens

When a session starts, the controller creates a URL and a token. EAS stores them encrypted. EAS returns them only while the session is in progress. After the session stops, the session response has no connection details.

EAS CLI writes the URL and token to **.env.eas-simulator**. The expo.dev session page hides the secret values. Keep the file out of Git and out of CI logs and artifacts.

## The browser preview

The browser preview has its own URL. When the preview is gated, the URL contains a session token. The preview page does not require an Expo login. The page moves the token out of the address bar after it opens.

Because the preview does not require a login, share the preview URL only with people who should control the device.

## Artifact download URLs

Each artifact has a download URL that contains a random key. The URL does not require an Expo login, so it works as a capability: anyone who has the URL can download the file. The URL redirects to a signed storage URL that expires after one hour. If the account is disabled, the download is blocked.

## Metro tunnels

For live edits, you start Metro with a public tunnel. The tunnel URL is random, which makes it hard to guess, but the URL does not require authentication. Anyone who has the URL can fetch your JavaScript bundle while the tunnel runs. Stop Metro when the session ends.

## Network traffic

By default, all network traffic from the remote device exits from EAS infrastructure. With local egress, iOS Simulator traffic that honors the system proxy exits from your computer instead. The local egress client refuses connections to local, private, link-local, and multicast addresses on your network. To let the simulator reach a server on your computer or your network, list each destination as an exact `host:port` with `--egress-allow`. See [Network inspection](/preview/eas-simulator/how-it-works/network-inspection/).

## What EAS does when a user is removed

If the user who started a session is deleted, EAS stops the session.

## Common questions

### Can another account see my session?

A session belongs to an EAS project. EAS checks permissions on the account that owns the project. People outside the account can reach the session only if they have one of its secret URLs or tokens.

### What should I do if a token leaks?

Stop the session. Connection details are not returned after a session stops. Start a new session to get new tokens.

### Is the app I install private?

The app installs on the remote device for the session. Artifacts from the session, such as screenshots, use capability URLs. See [Security and data](/preview/eas-simulator/reference/security-and-data/) for retention.
