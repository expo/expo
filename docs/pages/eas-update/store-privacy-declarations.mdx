Google Play requires every app with a store listing to complete the [Data safety form](https://support.google.com/googleplay/android-developer/answer/10787469) in Play Console. The form covers every library in your app, so your answers include what `expo-updates` sends to Expo Update. This guide lists that data and the form answers that match it.

> **info** You are responsible for the accuracy of your Data safety declarations. This guide covers only the data that `expo-updates` and Expo Update handle. Combine it with the data practices of the rest of your app before you submit the form.

## What expo-updates sends off the device

When your app checks for an update or downloads an asset, `expo-updates` sends an HTTPS request to Expo Update. The request carries the following headers:

| Header                                                                                                           | What it contains                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EAS-Client-ID`                                                                                                  | The [Expo Services client ID](/eas/observe/reference/client-id/), a random identifier for one installation of your app. It is generated on the device and is not derived from a hardware or account identifier. |
| `Expo-Platform`, `Expo-Runtime-Version`, `Expo-Protocol-Version`, `Expo-API-Version`, `Expo-Updates-Environment` | Facts about the build and the updates protocol.                                                                                                                                                                 |
| `Expo-Current-Update-ID`, `Expo-Embedded-Update-ID`                                                              | The IDs of the update that is running and the update embedded in the build.                                                                                                                                     |
| `expo-channel-name`                                                                                              | The channel from your app config.                                                                                                                                                                               |
| `Expo-Extra-Params`                                                                                              | Values your app sets with [`Updates.setExtraParamAsync()`](/versions/latest/sdk/updates/). The library sends nothing here unless your code sets a value.                                                        |
| `expo-expect-signature`                                                                                          | Present when [code signing](/eas-update/code-signing/) is configured.                                                                                                                                           |

Like every network request, the request also exposes the device's IP address to the server.

The library does not send personal information such as a name, email address, or account ID. It does not read the device's location, contacts, or files.

## What Expo stores

Expo Update stores the client ID and the IP address of each request for 90 days. It uses them to count installations per update and to derive an approximate location, such as the country, for usage insights. Expo processes this data on your behalf, as your service provider, under Expo's data processing agreement. See [privacy explained](https://expo.dev/privacy-explained) for what Expo collects across its services.

## Complete the Data safety form

The form has three parts that your Expo Update usage affects. The answers below assume you use Expo Update as your update server. If you [host updates yourself](/eas-update/standalone-service/), the same headers go to your server, and you declare what your server stores instead.

### Data collection and security

| Question                                                              | Answer                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does your app collect or share any of the required user data types?   | **Yes**. The client ID is a device identifier, and the IP address is used to infer approximate location.                                                                                                                                                                                              |
| Is all of the user data collected by your app encrypted in transit?   | **Yes** for Expo Update. The library sends every request over HTTPS. Answer for your whole app.                                                                                                                                                                                                       |
| Do you provide a way for users to request that their data is deleted? | Google allows **Yes** when you give users a way to request deletion, or when collected data is deleted or anonymized automatically within 90 days of collection. Expo Update deletes request data after 90 days. The answer covers your whole app, so base it on your own deletion practices as well. |

### Data types

Select these data types for Expo Update:

- **Device or other IDs**: the client ID. Google lists installation identifiers in this category.
- **Location > Approximate location**: Google's definition includes location inferred from an IP address.

### Data usage and handling

For each selected data type, the form asks how the data is collected and used. Use these answers:

| Question                                    | Device or other IDs          | Approximate location |
| ------------------------------------------- | ---------------------------- | -------------------- |
| Is this data collected, shared, or both?    | Collected                    | Collected            |
| Is this data processed ephemerally?         | No                           | No                   |
| Is this data required, or can users choose? | Required                     | Required             |
| Why is this user data collected?            | App functionality, Analytics | Analytics            |

The data is **collected** rather than **shared** because Expo acts as your service provider. Google's form treats a transfer to a service provider, an entity that processes data only on your behalf and on your instructions, as collection by your app, not as sharing with a third party.

The data is **required** because `expo-updates` sends the client ID on every update request. Google allows **optional** only when every user, in every region, can opt out.

## Expo Observe

If your app also includes `expo-observe`, add the declarations in [App store privacy declarations for Expo Observe](/eas/observe/reference/store-privacy-declarations/). Both libraries use the same client ID, so the **Device or other IDs** entry covers both.
