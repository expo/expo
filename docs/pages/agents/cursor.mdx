Cursor is an AI-first code editor built on VS Code. It can edit across multiple files, run terminal commands, and work autonomously with its agent. Expo projects created with `create-expo-app` are scaffolded with an **AGENTS.md** file that Cursor reads directly. It can also check Expo Services and Expo CLI logs, fetch documentation from the Expo Model Context Protocol (MCP) Server, use Expo Skills for best practices, manage your Expo Services deployment workflow, and more.

## Quick start

<Step label="1">

### Download Cursor

Download and install Cursor from the [Cursor website](https://cursor.com). For setup details, see the [Cursor documentation](https://cursor.com/docs).

To use Cursor in your terminal, install the Cursor CLI. For other install methods, see the [Cursor CLI documentation](https://cursor.com/docs/cli/installation).

<Terminal cmd={['$ curl https://cursor.com/install -fsS | bash']} />

</Step>

<Step label="2">

### Create a new Expo project

Create a project with the following command or ensure your existing project has the latest expo package installed.

<Terminal
  cmd={{
    npm: ['$ npx create-expo-app@latest'],
    yarn: ['$ yarn create expo-app'],
    pnpm: ['$ pnpm create expo-app'],
    bun: ['$ bun create expo'],
  }}
/>

</Step>

<Step label="3">

### Install the Expo plugin

Install the official Expo plugin so Cursor knows Expo conventions and can work with your Expo Services projects. The plugin installs Expo Skills and registers the Expo MCP Server.

<Tabs>

<Tab label="Cursor editor">

Open **Customize** in the Cursor sidebar and find the **Expo** plugin. Select **Install**, then choose a project or user scope.

You can also add the plugin from the [Expo page in the Cursor Marketplace](https://cursor.com/marketplace/expo). That page shows the `/add-plugin expo` command for the Agent panel.

Then sign in to your Expo account. In **Customize**, open the **MCPs** tab and select **Authenticate** next to `expo`. Complete the sign-in in your browser. After the sign-in, `expo` appears under **Connected**.

</Tab>

<Tab label="Cursor CLI">

Start the Cursor CLI:

<Terminal cmd={['$ agent']} />

In the session, type `/plugin` and open the **Marketplace** tab. Search for **Expo**, select the plugin, and select **Install for you (user scope)**.

Then sign in to your Expo account. Type `/mcp` in the session, select **Expo**, and select **Login**. Complete the sign-in in your browser.

</Tab>

</Tabs>

<Step label="4">

### Open your project and start prompting

Open your project in Cursor, then open the Agent panel and describe what you want to do.

With the Cursor CLI, run `agent` from your project root instead:

<Terminal cmd={['$ cd my-app', '', '$ agent']} />

</Step>

<Step label="5">

### Verify setup

In Cursor's Agent panel, enter the following prompt to confirm it can read your project:

```text Example prompt
Open package.json and tell me which Expo SDK version this project targets.
```

If the agent replies with the SDK version from **package.json**, the agent is reading your project correctly.

</Step>

## How Cursor reads your Expo project

When you open your project in Cursor, it reads the scaffolded **AGENTS.md** file at the project root, along with any nested **AGENTS.md** files in subdirectories. **AGENTS.md** points Cursor to the documentation for your project's Expo SDK version and holds any project-level instructions you add. **AGENTS.md** is committed to your project, so a developer's session starts from the same context inside Cursor.

You can also add Cursor-specific rules under **.cursor/rules/**.

## Example prompts

After setup, describe Expo tasks in plain language. For example:

| Task              | Example prompt                                                                    |
| ----------------- | --------------------------------------------------------------------------------- |
| Upgrade the SDK   | Upgrade this project to the latest Expo SDK and fix any breaking changes.         |
| Add navigation    | Add a tab navigator with Expo Router and a new settings screen.                   |
| Automate builds   | Create a workflow with Expo Workflows that builds the app on every pull request.  |
| Debug a build     | My latest iOS build failed. Read the Expo Build logs and tell me what went wrong. |
| Add notifications | Configure expo-notifications and show a local notification when the app launches. |
| Set up CI/CD      | Create a CI/CD workflow that builds on every PR.                                  |
| Add native UI     | Add a SwiftUI picker component to my Expo app.                                    |
| Check feedback    | Show TestFlight feedback for my app.                                              |
| Verify the UI     | Take a screenshot and verify the blue circle view.                                |

For more examples, see the Example prompts sections of [Expo Skills](/skills/#example-prompts) and [Expo MCP Server](/mcp/#what-does-expo-mcp-server-do).
